# Pro 6 自主移植进展

目标：继续本机启动链研究和最小原生 Linux 实验，不以没有公开成熟方案为终点。

用户已说明此机为开发机，无需保存用户数据，必要时允许清除。仍保留设备自身校准及启动恢复材料，以减少无恢复路径的硬件损失。锁屏、账号凭据不写入研究文件。

## Root 入口更正

从实机 Settings.apk 的 DEX 反汇编确认：FlymeRootRequestActivity 是按 UID/PID 请求的应用授权页面，缺少参数会退出。之前把它当作系统 Root 申请入口不准确。

真正的系统开启流程由安全设置调用 com.meizu.action.ROOT，指向魅族账号 OpenSystemRightActivity，并检查 Flyme 登录状态。此 Activity 有签名权限保护，shell 直接启动被拒绝；通过正常安全设置界面可以进入。

本轮通过正常设置界面进入“系统权限开放声明”。用户在手机上自行输入了 Flyme 账号密码，之后系统自动重启。ADB 恢复时读取到 ro.flyme.root.state=1，/system/xbin/su 存在且为 setuid。Android 当时尚未完成启动，su 0 id 请求授权时因 ActivityManager 尚不可用而失败。后续需等待启动完成再实测 uid=0，不把 su 文件存在等同于提权实测成功。

证据：settings-root-dex-disassembly.txt、account-root-dex-disassembly.txt，以及本轮命令输出。没有自动填写 Flyme 账号密码。

## LK 实际检查路径的重要新线索

之前已证明原厂镜像中外层散列和证书的数学关系，但那不证明 LK 在每条运行路径都执行它们。

进一步反汇编：

- 正常 boot 载荷读取路径 0x460078a4，在0x46007964调用0x46007424。
- 0x46007424 调用0x460072c8；后者只有 movs r0,#0 / bx lr，是返回成功的空实现。
- 0x46007404 也调用该空实现，之前将状态字清零。
- 这些状态函数通过 GOT 槽0x4604f104访问状态字0x46050534，输出 verifiedbootstate 的函数也读取同一字。
- 0x46007424 对非3状态清零，随后返回成功并追加状态字符串；状态3走错误显示分支。

用 Unicorn 2.1.4 离线模拟原厂机器码：给载荷参数传入完全未映射的0xdead0000，模拟没有发生载荷读取异常。0x46007404对初始状态0/1/2/3均清零并返回0；0x46007424对0/1/2返回0，对3返回-1。模拟只拦截显示函数和命令行追加函数，不将模拟称为实机启动验证。

证据：lk-state-emulation.json、lk-state-global-resolution.json、lk-boot-payload-loader.txt、lk-verified-state-function.txt。

结论：这段运行路径中的检查是空实现，green属性不能作为签名检查已发生的证据。仍需继续追踪更早阶段、其他路径及安全固件是否另有独立验证；不能仅据此宣称整个设备未验证签名。

### 本机分区备份

位置：device-backup/20261018-121403/，索引manifest.json；latest-device-backup.txt记录绝对路径。共20个分区/启动区，加主备GPT共22项：

boot、recovery、lk、lk2、seccfg、frp、devinfo、proinfo、nvcfg、nvram、nvdata、protect1、protect2、tee1、tee2、scp1、scp2、para、mmcblk0boot0、mmcblk0boot1。

每项按/sys/class/block中的扇区容量验证长度；保存主机SHA256，并核对主机SHA1与设备端第二次sha1sum读取。主备GPT另检查头部CRC32和分区数组CRC32。nvdata等从运行系统读取，不宣称是暂停所有服务后的整机一致快照；校准材料仅保存本地，已将device-backup加入gitignore。

Flyme su会把两行授权调试日志写入stdout，首次原始boot读取多出178字节，长度检查因此拒绝。后续去除严格匹配的su日志前缀后，完整分区SHA1与手机端匹配；含调试前缀的boot.img.part不在有效备份清单中，不可作为刷写输入。

Android旧dd不支持status=none。GPT使用root只读dd到/data/local/tmp下临时文件，再仅对这些新建文件设为0644供ADB读取；没有修改块设备权限或写入任何启动分区。

### 首次独立 Linux 启动实验（驱动安装后）

Fastboot驱动已安装，devices返回80QBCNK225PS。getvar all报告unlocked=yes、secure=no；不能把Android ro.boot.flash.locked属性当作该Fastboot实现的最终状态。fastboot reboot返回OKAY且Android ADB恢复。fastboot boot成功传输镜像但启动命令返回unknown command，证实无内存启动入口。
