# 屏幕与触控适配记录

目标：手机本机 Ubuntu 图形桌面和触控；命令行启动不构成完整完成。

当前实机证据：
- /sys/firmware/devicetree/base/chosen/atag,videolfb 为小端 MediaTek ATAG；首字段给出 0xb9ba0000。
- 已用只读 mmap 导出该地址的 1080x1920、BGRA8888、4352 字节行宽画面，evidence/lk-framebuffer.png 正确显示完整 MEIZU 标志。因此地址、行宽、像素布局有直接证据。
- /dev/mem 映射为 device memory，Python 切片复制写入触发 SIGBUS；改为对齐 32 位 scalar store 后完成色块写入。msync 对设备映射返回 EINVAL，脚本已删除 flush。物理面板刷新效果等待用户观察，不能从读回缓存推断成功。
- 原厂实机日志证明 synaptics_dsx 位于 11011000.i2c / i2c-4 / 4-0020；原厂设备树提供 GPIO68 IRQ、GPIO201 和203电源、GPIO211 reset；不能将原厂 IRQ 数68直接当成上游 EINT 线号，参考 EINT 映射 GPIO68 对应 EINT7。
- 新增 mt6797-meizu-pro6-display-v10.dts，simple-framebuffer +仅启用 I2C4；尚未刷入。
- 第一次显示编译完成，但 DRM=m 导致 simpledrm、simplefb 是模块；当前第二次编译禁用 simpledrm，明确 FB_SIMPLE=y，避免启动缺模块。
- Ubuntu 官方 APT 正在安装 Xfce4/Xorg/libinput/Onboard/Weston，尚未验证桌面启动。

参考：Linux 6.18.57 本地 simple-framebuffer.yaml、syna,rmi4.yaml；Gemini 主分支固定提交598040b5881d9d17d144dfc07fda0ea138e5e9db 的0005/0006/0086补丁已下载供研究，尚未应用。
